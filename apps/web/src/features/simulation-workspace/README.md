# Comparaison de simulations

`SimulationWorkspace` est la vue Simulations d’`AnalysisJourney`, utilisée dans les résultats de l’Assistant et le dossier d’analyse. Elle ouvre une référence calculée, puis permet de comparer jusqu’à trois hypothèses sur le même graphique. Elle réutilise `ChartContainer` d’`ArchivedChart.tsx`, adapté de l’archive FrontUI Recharts déjà documentée dans `analysis-workspace/README.md`, et les fiches/source dialogs du produit. Aucun jeu de courbes de démonstration n’est embarqué.

Le moteur existant `POST /v1/simulation/forecast` calcule 2 000 trajectoires par rééchantillonnage des rendements historiques. La date de départ affichée est celle du dernier cours du jeu, et les abscisses sont des séances après ce départ. Les horizons proposés sont 5, 20 et 60 séances; ce décalage ne devient pas automatiquement la semaine civile de la recherche. Le calcul garde la même graine et les mêmes trajectoires pour toutes les hypothèses. La variation et son moment d’application viennent des réglages utilisateur. Associer un événement conserve sa source, sans inférer sa probabilité ni une amplitude de réaction.

Les modifications déclenchent un calcul après 450 ms. Le nettoyage de l’effet annule la requête précédente et une réponse annulée ne peut pas mettre à jour le résultat. Les courbes et chiffres restent identifiés comme non actualisés pendant un changement ou une panne. `runAnalysisForecast` vérifie le titre, les unités, l’horizon, les identifiants, noms, sources, variations et décalages retournés, ainsi que la continuité des jalons. Seuls les résultats acceptés sont transmis au parent et conservés dans le navigateur par compte et analyse; ils alimentent aussi la vue Entreprise. Les modifications non calculées ne remplacent pas ce dernier résultat.

Le graphique compare les médianes sur une échelle commune; la bande p10–p90 appartient au scénario sélectionné. Les cartes donnent les médianes finales, fourchettes, variations depuis le cours initial et écarts à la référence. Les points s’explorent aussi depuis le tableau accessible au clavier. Méthode, limites et contrôle chronologique restent consultables dans les détails. Le rapport général est masqué pendant cette vue dans les deux conteneurs pour éviter de dupliquer le dossier sous les réglages.

Validation locale : `npm run typecheck --workspace @investoros/web`, `npm run build --workspace @investoros/web` et `INVESTOROS_TEST_ANALYSIS_ID=<uuid-NVDA-Mateo> node scripts/test-simulation-workspace.cjs`. Le test utilise l’API réelle pour vérifier les variations, les décalages, l’horizon, les sources, la persistance, la suppression et le clavier mobile. Des injections de panne et de réponse incorrecte vérifient la reprise et le rejet des résultats incohérents; un retard contrôlé vérifie l’annulation d’un calcul dépassé. Les captures sont validées et décodées avant publication. Cette évolution est vérifiée localement; elle n’a pas été déployée sur AWS dans cette intervention.
